# PDF physical size implementation plan

> Execute inline using superpowers:executing-plans.

**Goal:** Preserve each source page's physical crop size when exporting single PDFs and A4 tiles.
**Architecture:** Keep preview coordinates unchanged. Convert them using each page's UserUnit for both raster resolution and layout dimensions. Share the maximum physical crop size calculation between PDF and JPG exports.
**Tech Stack:** Existing PDF.js 3.11.174, pdf-lib 1.17.1 and Canvas.
**Spec:** The accepted investigation/proposal in this conversation. The user's actual PDF is unavailable; do not claim its symptom is verified resolved.

## Global constraints

- Preserve existing margins, gaps, orientation selection and preview/crop interactions.
- DPI changes resolution, not physical dimensions. Account for UserUnit exactly once.
- Implement, verify, publish and check the deployed page as authorized.

## Review focus

- UserUnit below and above 1; default 1 remains unchanged.
- Mixed units across pages; maximum dimensions use physical sizes.
- Both PDF and JPG layout paths use the same physical sizes.
- Zoom and DPI do not alter physical dimensions.
